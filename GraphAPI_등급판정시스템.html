Graph API 권한 등급 분류 기준 요약 — 3기준 × 2값 = 8조합 → G1/G2/G3 · 판정 전에 한 번 확인하세요

1차 분류 — Graph API를 3가지 기준으로 나눕니다

① 정보 유형
어떤 데이터에 접근하는가?
G
일반 정보
조직도, 메일 주소, 부서·직급, Teams 팀 목록, 라이선스 현황
S
민감 정보
High — 메일 본문, 첨부 원문, Teams 채팅, SPO 문서 원본
Low — 메일 제목, 첨부파일명, 채팅 목록, 접속 기록, 상세 일정
② 접근 범위
누구의 데이터에 접근하는가?
D
개인/특정 계정 — Delegated
로그인한 사용자가 원래 접근 가능한 범위 내에서만 동작
A
전사 계정 — Application
사용자 없이 앱 단독 실행. 별도 제한이 없으면 테넌트 전체에 적용
③ 작업 유형
어떤 작업을 하는가?
R
Read — 데이터 표시·적재 (일방향)
W
Create/Update — 변경·업로드·발신 (양방향)
X
Delete — 운영 관리 전용. 현업 부여 제외, 등급과 별개로 별도 협의

8조합 → 3등급 매핑

GDRGDWSDRSDW
G1
개인 권한 정보 활용 기존 개인 계정 권한으로 다룰 수 있는 정보 · 운영그룹 주관, 필요시 보호그룹 공유
GARGAW
G2
전사 일반 정보 활용 전사로 확대될 수 있는 일반 정보 · 운영그룹 주관 및 보호그룹 공유
SARSAW
G3
전사 민감 정보 활용 전사로 확대될 수 있는 민감 정보 · 보안 요건 충족 후 운영성 검토
핵심 — 접근 범위가 Delegated면 정보 민감도와 무관하게 G1입니다. 앱이 사용자 본인의 권한 범위를 넘지 못하기 때문입니다. Application일 때만 정보 유형이 G2와 G3를 가릅니다.

★ 접근범위 재판정 룰 (RULE-SCOPE-D)

Application으로 신청했더라도, 대상이 한정되어 있으면 Delegated로 재판정합니다

아래와 같은 대상 한정 표현이 활용목적·활용데이터·활용계정에 있으면 접근범위를 D로 낮춰 판정합니다.

특정 사서함공유 사서함특정 팀 특정 채널특정 사이트특정 사용자 로그인한 사용자본인 계정담당자 1인 Sites.Selected

단, 전사전체 사용자전 임직원모든 팀 같은 전사 표현이 함께 있으면 재판정하지 않고 범위 상충으로 표시합니다.

⚠ Application 권한은 별도 제한이 없으면 실제로는 테넌트 전체에 적용됩니다. "특정 사서함만 쓰겠다"는 선언은 코드 레벨의 약속일 뿐 부여된 권한 자체를 좁히지 않습니다. 따라서 재판정으로 낮아진 등급은 아래 기술적 범위 제한 조치의 이행을 전제 조건으로 하며, 미이행 시 원 등급으로 환원합니다.
· Exchange Online — RBAC for Applications(권장) 또는 New-ApplicationAccessPolicy
· SharePoint/OneDrive — Sites.Selected + 대상 사이트에만 권한 부여
· Teams — RSC(Resource-Specific Consent) 또는 *.Group 계열 권한
· 공통 — 사용자 로그인 컨텍스트가 있으면 Delegated 권한으로 전환 (최우선 대안)

2차 분류 — 활용 방식에 따라 등급을 조정합니다

데이터 최소화非필수 컬럼 제외·마스킹 로직 구현 G3 → G2
정보주체 인지/동의대상 데이터 주체 전원이 저장·2차 활용을 인지·동의 G2 → G1
저장·2차 가공저장 없이 통계·집계값만 활용 G3 → G2
영향 범위/활용 규모임원·직책자 대상이거나 전사 × 고빈도(Daily·실시간) G2 → G3
하향은 최대 1등급까지만 적용합니다. 상향·하향 요인이 동시에 발동하면 상쇄되고 담당자 확인 대상이 됩니다. 미기재 항목은 유리한 방향으로 해석하지 않고 보완 요청으로 넘깁니다.

신청서 작성 시 꼭 지켜주세요

공식 권한명으로 기재
Mail.Read : 특정 공유사서함 알람 수신 처리 형식으로, Microsoft Graph 공식 권한명 + 활용목적을 함께 적어 주세요.
대상 범위를 구체적으로
어떤 사서함·팀·사이트를 쓰는지 명시해야 등급 하향과 범위 제한 조치의 근거가 됩니다.
권한 만료일은 필수
미기재 시 접수 보류됩니다. 최대 1년 이내를 권장하며, 만료 시점에 재심사합니다.

2 역할 상세 및 등급 판정

  







  M365 관리자 권한 등급 분류 기준 요약
    — 3기준 × 2값 = 8조합 → A1/A2/A3 · Graph API 기준(G1/G2/G3)과 동일 구조
  

    

      
1차 분류 — 3가지 판정 기준

      

        

          
① 영향 범위 (Scope)
얼마나 넓게 적용되는가?

          
S

            서비스·기능 한정
단일 제품 또는 단일 기능 영역에만 적용

          
T

            테넌트 전역
디렉터리 전반(사용자·그룹·역할·앱·정책·도메인) 또는 전 서비스 교차

        

        

          
② 작업 유형 (Operation)
무엇을 할 수 있는가?

          
R

            읽기 전용
조회·모니터링·보고만 가능. 설정 변경 불가

          
W

            구성 변경
생성·수정·삭제·정책 변경 가능

        

        

          
③ 민감 자산 접근 (Sensitive)
민감 자산에 닿는가?

          
N

            없음
권한 상승 경로도 콘텐츠 접근 경로도 없음

          
P

            있음

            (a) 권한 상승 — 역할 할당 · 자격 증명/MFA 변경 · 앱 권한 동의 · 조건부 액세스/인증 정책 · 도메인/페더레이션 변경

            (b) 콘텐츠 접근 — 메일 · 파일 · 채팅 · 문서 원문 열람 또는 열람 위임 설정 가능

        

      

    


    

      
8조합 → 3등급 매핑

      

      
핵심 — 민감 자산 접근(P)이 있으면 범위·작업과 무관하게 A3입니다.
        Graph API 기준에서 "Delegated면 무조건 G1"이 등급을 결정했듯, 관리자 역할은 "민감 자산 접근"이 등급을 결정합니다.
        권한 상승과 콘텐츠 열람은 읽기/쓰기·범위와 무관하게 최고 위험이기 때문입니다.

    


    

      
등급별 승인 절차 및 할당 방식

      

        

      

    


    

      
운영 원칙

      

        
전역 관리자 최소화

          
조직당 2~4명 이내로 제한하고, 상시 할당 대신 PIM 적격(Eligible) 할당으로 운영합니다.
            계정 잠금에 대비해 권한 있는 인증 관리자를 최소 1명 유지합니다.

        
최소 권한 역제안

          
요청 시 "수행해야 할 작업"을 먼저 확인하고, 그 작업에 필요한 최소 권한 역할을 역제안합니다.
            예: 암호 재설정만 필요하면 전역 관리자가 아닌 암호 관리자 · 기술 지원팀 관리자.

        
정기 회수

          
분기별 전수 조사로 미사용 할당을 회수하고, 할당 기간 만료 시 자동 회수 후 재심사합니다.
            모든 관리자 계정에 MFA를 필수 적용합니다.
